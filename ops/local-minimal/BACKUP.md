# local-minimal — 起動と毎日のバックアップ

日常の確かめ方と、止まったときの直し方は [README](../../README.md)。ここは仕組みを直す人向け。

## ファイル

| ファイル | 中身 |
|---|---|
| `pc/bootstrap.py`・`pc/windows-boot.mjs` | Windows 起動時に WSL 内の暗号化領域を開き、サービスを順に起動する |
| `pc/*.service`・`pc/*.timer`・`pc/compose.yaml` ほか | 本番専用 Docker・Tunnel・バックアップのタイマー、DB・ログイン・DB API のコンテナの定義 |
| `runtime.py` | アプリ（`--app`）と Jobs（`--jobs`）を起動する前の検査。設定・版・置き場所が記録と合わなければ起動しない |
| `transport.py` | Tunnel の設定の検査 |
| `periodic.py` | 1日1回のバックアップの進行役（採取 → Drive へ保存 → 古い世代の整理） |
| `backup.py`・`backup-codec.mjs` | 採取・暗号化・復元の確認 |
| `offsite.mjs`・`drive-storage.mjs` | Google Drive への保存と読み戻し |
| `snapshot-retention.mjs`・`snapshot-cleanup.mjs`・`cleanup-runner.mjs` | 古い世代の整理 |
| `*.example.*` | 設定の形の例（値は入っていない） |

## バックアップの動き

1. **採取** — アプリも Jobs も止めない。PostgreSQL の読み取り専用スナップショットから `pg_dump` を取り、同じ時点の全表の指紋・画像の一覧と突き合わせる。採取の途中で画像の削除や Jobs の送信が重なったら、その回は取りやめる（前回のバックアップがそのまま残る）。
2. **中身** — DB 全体（`pg_dump` の custom 形式）、ロールと権限（パスワードは含めない）、画像の全ファイル、Jobs の履歴（`journal.json`・ロック・状態）。
3. **暗号化** — `TUATPC01`（AES-256-GCM）。鍵は README の「鍵とアカウント」のバックアップの鍵。
4. **復元の確認** — 毎回、ネットワークを切った使い捨ての PostgreSQL へ復元し、全表・権限・画像を照合する。本番の DB へは復元しない。照合が通ってはじめて受領証（`local-snapshot.json`）を更新する。
5. **Drive へ保存** — 暗号化したファイルを送り、全体を読み戻して一致を確かめる。
6. **整理** — 手元は新しい順に24、Drive は96、加えて30日分は1日1つ、最新は必ず残す。消す候補があるときだけ、対象を1つずつ確かめ直してから消す。

## 止まる条件（わざと止めている）

取得に失敗したときに「0件」として先へ進まないための作りで、次のようなときは新しいバックアップを作らない（その回を取りやめて次回に回すものと、人が確かめるまで止まるものがある。正確な条件は `backup.py`・`periodic.py` の検査と、それぞれの `.test.py`）。

- 通知の配信が確保されたまま終わっていない。採取の途中で Jobs の送信や画像の削除が重なった。
- DB にどこからも参照されていない画像がある、または参照されている画像がない（保存の途中で止まった投稿など）。設定の `retainedUnreferencedImages` に、確かめ済みの画像を大きさとハッシュつきで書いたものだけは例外にできる。
- 決めた以外のコンテナ・サービスが DB や画像に触れる状態にある。
- Drive への送信の結果が分からない（送り直さない）。
- 前回の中断の記録（`capture-state.json`・`periodic-attempt.json`）が残っている。直し方は README の「止まったとき」。

バックアップが古い・失敗しただけでは、アプリの書き込みは止めない。書き込みを止めるのは、アプリと DB の組が記録と合わないときと、心拍（120秒）が途切れたとき。

## 知っておくこと

- 受領証は48時間まで有効とみなす。タイマーは前回の完了から1日後、起動後は5分後に走る。
- 鍵・設定（ログインの署名鍵、Google・GAS・通知の鍵など）はバックアップのファイルには入らない。別に暗号化した復旧用の一式で持つ（[handoff](../handoff/README.md)）。
- 1回の上限は16GiB・10万ファイル。復元の確認に使う DB は512MiB なので、それを超えたら設定の見直しが要る。
- コードには、アプリを一時停止して採取する古い方式（`captureMode` が `online` でないとき）と、移行のときの試験機（`tuat-surface-trial-*`・`tuat-local-mirror`）が動いていないことを確かめる検査が残っている。本番では使っていないが、検査を外すには Linux での試験が要る。

試験の走らせ方は [ops/README.md](../README.md)。
