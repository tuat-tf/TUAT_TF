## 原因と確度

直接確認できる障害は、GAS応答のJSON解析失敗と、それを受けた定期同期の継続停止。

`src/lib/sheet-sync/gas-client.ts` の `readGasJson` はHTTP状態や本文の種類を区別せず、JSON.parse失敗を一律「公開設定を確認」へ変換する。この文言だけでは公開設定不備、Google側の一時エラー、別HTML応答等を特定できない。失敗時のHTTP状態・応答本文は同期履歴に保存されておらず、Google側の詳細原因は未確定。

最新の2件は送信待ち記録と対応し、`run.ts` の scheduledPushes / writeCells の失敗経路と整合する。返信送信元確認の失敗は `replies.ts` が別の「既存の返信を保持」文言へ変換するため、今回保存された2件のエラーとは異なる。取り込み全体の失敗や、10/1返信確認改修が原因とは判断しない。

`ops/pc-jobs/scheduler.mjs` の dueJobs は前回statusがsuccess以外なら翌日の枠も除外する。今回のfailed状態を保ったままでは、次の0時にも記録同期は実行されない。再起動だけでも解除されない。失敗履歴を成功に書き換えていない。

DBには部分失敗でもstatus=successを記録する一方、runnerはfailedとするため、状態の見方にも注意が必要。API自体は部分失敗を返しており、runnerの判定は実装どおり。
