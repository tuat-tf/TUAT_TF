### 1. P1: アプリを主入力にする人のシート編集が取り込まれない

- 状態: コード確認・合成テストで再現。
- 場所: `src/lib/sheet-sync/run.ts:215-227`。
- `record_source=app` の経路は `computeMemberPull(..., "merge_nonempty")` で更新差分を計算するが、`pulled.inserts` しか回収していない。`pulled.updates` を更新キューにも更新件数にも加えていない。
- 例: DBの感想が「old」、CSVが「new」でも、定期同期は更新0件で正常終了する。そのCSVの署名まで保存され、次回以降は未変更として処理を省略し得る。
- 7/27の「空でないシート編集を反映する」という記録・直前のコメントとも不一致。
- 修正方向: 更新差分と件数を回収し、アプリ主入力・シート主入力の両経路を同期本体を通して検証する。

### 2. P1: 通信失敗後の再送が空欄への変更を失う

- 状態: コード確認・合成テストで再現。
- 場所: `src/lib/sheet-sync/run.ts:165-175,331-340`、`src/lib/sheet-sync/push.ts:31`。
- 通常の保存は `appToCellsFull` で空欄も送る。一方、シート主入力の再送は `appToCellsNonEmpty` を使用し、空欄を省略する。
- 例: 距離5kmを残し感想だけ消す。即時送信が失敗すると、再送は距離5kmだけ送り、感想はシートに残したまま `pending_sheet_push=false` にする。次の取込が実行されると古い感想が復活し得る。すべての送信項目が空欄なら送信キューにも入らず、未送信のまま残る。
- 修正方向: 明示的な編集の再送と初回の非破壊移行を分離し、削除・0への変更を含む送信内容を保持する。

### 3. P1: 古い送信の完了が、新しい編集の未送信フラグを消す

- 状態: コード上の競合を確認。実通信を伴う同時編集の再現は未実施。
- 場所: `src/app/api/sheets/push-record/route.ts:54-65`、`src/lib/sheet-sync/run.ts:331-340`。
- 送信開始時の記録をGASへ送った後、IDだけを条件に `pending_sheet_push=false` を保存する。送信中に別端末等で記録が変わったかを照合していない。
- 新しい編集の送信が失敗し、その後で古い送信が成功すると、新しい編集まで送信完了扱いになり、自動再送の対象から外れる。シート主入力では古い値の再取込にもつながる。
- 修正方向: 内容の版番号等を送信時に保持し、その版が変わっていない場合だけ送信完了を確定する。シート側の書込順序も併せて制御する。

### 4. P2: アプリで削除した練習記録が同期で復活する

- 状態: 削除経路をコード確認、DBに存在しないCSV行が新規挿入対象になることを合成テストで確認。
- 場所: `src/components/cards/PostOwnerMenu.tsx:96-115`、`src/lib/sheet-sync/pull.ts:65-81`。
- アプリの削除はDB行だけを削除する。対応するシート行や削除履歴は変更しない。CSVに値が残っていると、取込範囲内で次にそのCSVを解析した際に新規記録として復活する。
- CSV署名が同じ間は省略されるため、必ず直後の同期で復活するわけではない。シートの別行を編集する等で再解析されると起き得る。
- 削除時に回収したコメント・いいねは復元されず、別IDの投稿になる。画面の「元に戻せません」という案内だけでは実際の挙動を説明できない。
- 日付変更も旧シート行を残すため、旧日付が再作成される同種の問題がある。
- 修正方向: シート連携中の削除・日付変更の仕様を決め、削除履歴による再取込防止、またはシート側操作との整合を実装する。
