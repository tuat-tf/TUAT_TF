# バックアップ負荷の修正（2026-10-22）

所有者の「修正して」に基づく作業。通常利用を優先し、旧15分周期・35分で保存停止という規則を変更する。別PC復旧や復号鍵の本人保管は、この修正の公開条件にしない。

## 再現と受入条件

- 現行d4cfda5は採取時にapp/Jobsをfreeze、Auth/RESTをpauseし、毎周期に全復元検証と39,437ファイルの再ハッシュを行う。
- 直近暗号文は約18.3MB。通常のPUTとGETに加え、古いローカル1件の整理だけでも同じ最新版をさらに2回GETしていた。通信量の請求実績との因果は未確認。
- 修正後は1日周期。採取時も通常利用を継続し、DBの同一MVCCスナップショットと画像・Jobsの整合を確認する。競合で採取できない場合は前回分を保ち、通常保存を止めない。
- 暗号化、外部保存先の1回の読戻し、日次の復元確認は残す。整理処理は同じ実行内で成功した読戻しを利用し、最新ETag/サイズ/SHAをHEADで再確認する。
- 本人・ロール・DB・画像・Jobsの状態と結果不明の履歴を保持。バックアップの失敗・欠如だけで保存を停止しないが、ホスト/DBの不一致・保守中・120秒の心拍切れは拒否する。
- コードの全ファイル検証はリリース起動時に残し、日次は実行コードと設定の既存sealを確認する。
