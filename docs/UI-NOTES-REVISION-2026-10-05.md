# ノート操作を「…」へ統一（2026-10-05）

担当: Codex。ノートの操作入口について、所有者から「共有と管理を分離する意味ではなく、全部『…』で統一」と訂正がありました。[前回の記録](UI-NOTES-POSTING-2026-10-05.md)の共有分離方針は、今回の指示で更新します。投稿フォーム・他画面のUI・DB保存処理は変更しません。

## 着手時の再現と受入条件

現コードの`NoteArticleActions`・`NoteDetailActions`と前回の合成スクリーンショットで、共有アイコンと管理「…」が2つの入口として出る状態を確認しました。記事一覧では、題名行による展開と、別の操作行に置いた共有・管理が表示されています。これは今回の「…へ一本化」という受入条件を満たしていません。

- フォルダ・記事詳細・記事一覧に出る操作入口は、共通`ActionMenu`の「…」だけとします。リンクコピー・他アプリ共有・編集・ピン留め・削除を同じメニューから選びます。項目がない場合は空のメニューを出しません。
- 公開ノートの閲覧者は、編集・削除権限がなくても「…」から共有できます。下書きでは共有項目を出さず、編集・削除・ピン留めは従来の権限でのみ表示します。
- 記事を読む展開操作は題名行に維持し、メニューを開く操作で記事が勝手に展開・折り畳みされないようにします。320pxの幅でも題名・展開・「…」のタップ領域を重ねません。
- リンクコピー・ネイティブ共有は直接の利用者操作で実行します。共有キャンセルでは余分にコピーせず、共有未対応・共有エラー時は既存のコピーへ復帰します。コピー失敗は通知します。
- 編集は共通の全画面フォーム、削除は共通確認を維持します。既存の未保存・保存中・保存結果不明時の確認と復旧は変更しません。
- 本番DB・環境変数・本番公開・push・稼働プロセスの停止は行いません。ビルド起動は親担当が一本化します。
