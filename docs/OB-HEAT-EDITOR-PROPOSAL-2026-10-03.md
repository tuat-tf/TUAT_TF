# OB戦 組み分け画面の簡素化（Codexへの提案）

2026-10-03 / Claude Opus 5.5。オーナーと試作を往復して決めた内容を、Codexの現行実装（origin/master `84f65ed`、`ObHeatEditor` / `MeetHeatBoard` / `MeetHeatPlan`）への変更提案としてまとめた。**実装は未着手。本番・DB・コードは変更していない。**

試作（架空データ92人、スマホ幅で動作確認済み）: `.contingency/ob-heat-proposal/ob-board-prototype.html`（Git対象外。ブラウザで直接開ける。操作内容はlocalStorageに残るので、上部の「最初に戻す」で初期化する）。

## オーナーのフィードバック（この提案の根拠）

1. 今の組み分け画面は**操作が多すぎて初見で使い方が分からない**。「もっと直感的に」。
2. **並び替え（ソート）機能は要らない**。資格記録順に並べ直す・上下で順番を動かす操作は不要。
3. **空き枠の表示・空き枠から人を入れる機能は要らない**。組には人がいる行だけ並べればよい。
4. **人数が多い場合**（1種目20〜30人）でも使えること。1人ずつ動かす前提にしない。
5. スマホでやりやすく。PCでも使える。
6. **男女で分ける意味はあまりない**（どの種目も男女連続で実施し、時間はほぼ同じ）。現役／OB・OGの切り替えも不要（出場表は10/02に対応済み）。
7. 跳躍・投てきの試技は**3回まで。追加試技なし**。風速は計測するか不明なので任意入力のまま。
8. 組分けの担当者は「OB戦2026」ロール（既存）。

## 提案する操作（これだけにする）

**「人を押して選ぶ → 画面下のボタンで移す」の1種類だけ。**

- 行を押すとチェックが付く（もう一度押すと外れる）。選択モードの切り替えボタンは置かない（常に選べる）。
- 1人以上選ぶと、画面下に固定のバーが出る。
  - 「N人を選択中：苗字・苗字」「選択をやめる」
  - 「1組へ」「2組へ」…（既存の組の数だけ）
  - 「新しい組へ」（選んだ人で組を1つ作る。トラックのみ）
  - 「未定へ」（選択に配置済みの人がいるときだけ）
  - **ちょうど2人を選んだとき**だけ「入れ替える」（組の中の順番の変更も、組をまたいだ交換もこれで行う）
- 組へ移した人は、その組の最後に付く。番号（レーン・順番・試技順）は**組の中の並び順で1から振り直す**。空き番号という概念を画面に出さない。
- 空になった組は自動で消え、組番号を詰める。
- 「一つ戻す」は残す（誤操作の保険。上部に小さく）。
- 「表から貼り付け」は残す（組分け担当が表計算ソフトで作った「組・番号・氏名」の3列を一括反映）。
- 組の一覧（「1組男 6」「2組男 6」…）を上部に横並びで出し、押すとその組へ移動（縦に長くなっても探さなくて済む）。
- 初めて開いたとき（全員未配置）は、自動で仮に組を作っておく。**ボタンとしての自動割り当て・並べ替えは置かない**。

### 現行画面から外すもの

`MeetHeatBoard` にある次の操作をなくす。

- 上下ボタン（一つ前へ／一つ後へ）
- 1人選択時の各番号の「ここへ」「入替」ボタン、空き番号の行表示（「空き」）
- 「1組の人数」入力、「組を追加」（→「新しい組へ」に統合）
- 「表示中を選択」、氏名検索（未配置の検索も含む）
- 「未配置をまとめて割り当て」ボタン（初回の自動配置に置き換え）
- 「人を選んで、移動先の組を押してください」などの長い説明文は1行に（「動かしたい人を押して選び、下のボタンで移します。2人選ぶと入れ替えられます。」）

残すもの: 未配置欄、欠場・出場取消欄（記録を消さない現行の扱いを維持）、保存時のrevision競合・未保存確認・保存失敗時の配置保持、満員なら操作全体を拒否する原子性（短距離は1組8人）。

### 既存のモデルで足りるもの

`MeetHeatPlan` の `assign(ids, group, capacity)`（まとめて移す・新しい組）、`place(id, group, order)`（埋まった番号なら交換＝「入れ替える」）、`unassign(ids)`（未定へ）、`fill(capacity)`（初回の自動配置）でほぼ足りる見込み。追加が要るのは「移動・交換のたびに組内の番号を1から詰め直す」と「空の組を消して番号を詰める」の2つ。

## 男女をまとめて1画面にする

- 現行は種目×男女（`ob_event_operations` の `event_name` が「男子100m」「女子100m」の別行）で別々に編集・表示している。プログラム詳細にも男女の切り替えがある。
- 提案: **種目ごとに1画面**。名前の横に小さく「男／女」を付け、組の見出しは中身が片方だけなら「1組（男子）」のように出す。順位は今どおり男女別（「男子2位」）。プログラムの種目詳細も男女切り替えをやめて1つの一覧にする。
- 実装上の注意: データは男女別の2行（それぞれrevision付き）。1画面で両方を保存すると、今のRPCだと2回の保存になり途中失敗があり得る。**両行を1トランザクションで保存するRPCを足す**か、少なくとも片方だけ保存された状態を画面で明示する必要がある。migrationが要る場合は、従来どおり両DBの退避・ROLLBACK試験・予備同期の対象確認を先に行う。
- **オーナーへの確認が必要**: 男女が混ざった組を許すか。許さないなら、男子を女子の組へ移す操作は理由を出して拒否する（男女別の2行のデータ構造をそのまま使える）。許すなら組番号を種目で共通にする必要があり、データの持ち方の変更になる。試作は混在を許している。

## そのほか

- 跳躍・投てきの試技上限を、OB戦では**3回**にする（現行の `MeetEvent` 検証は距離種目で最大6）。`obEventRule` 側で上限を持たせ、他大会の6回はそのまま使えるようにするのがよい。
- 風速は現行どおり任意（空欄可・0と負数も保存）。

## 確認したこと・していないこと

- 試作で、25人（300m）の自動配置、2人選んでの入れ替え、選んだ人で新しい組を作る、一つ戻す、をスマホ幅（375px）で動かして確認した。試作は架空データで、本番のコンポーネントではない。
- 現行実装のコードは、文言と `MeetHeatPlan` の公開メソッド、`ob_event_operations` の主キーだけを読んだ。細部の挙動（取り消し履歴、欠場欄の操作）は読んでいない。
- 実機（iPhone / Android）での確認はしていない。
