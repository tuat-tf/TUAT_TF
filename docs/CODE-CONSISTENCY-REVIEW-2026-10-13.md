- 会場・種目・PB・月別結果・大会・フォルダ・ノート・記事・スレッド・予定の単件削除は、対象1件の応答を確認してから成功処理へ進む。RLS等の0件と通信例外では一覧・画面を保持する。
- 種目並べ替えは全行upsertからsort_orderだけの更新へ変更し、古い測定方法の上書きと削除済み種目の再作成を防ぐ。種目名統合は実行前後の件数を確認し、件数変化/部分保存/結果不明を成功にしない。
- 会場・種目・結果の応答不明保存は、送信時のID/name・入力を保持して読取で結果確認。一致時に完了し、確認失敗では再送しない。読取成功の後のみ、同じID・同じ内容の明示再試行を許可する。編集再試行は旧値条件を付け、他者の変更を上書きしない。
- メニュー/予定の取込はcatch/finallyで操作状態を解除し、部分成功済み行を再送対象から除外する。保存/シート作成/削除の結果不明は確認導線と明示終了を設け、無確認再送を止める。管理行作成に先にUUIDを決め、応答不明後は同じIDを参照する。初回未達なら成功した不存在確認の後に再開できる。
- 未保存入力と保存中の閉じる操作は既存useFormDraft/FormModalへ統一。通常/シート入力の切替もdirty/busyを通知して既存確認ダイアログで守る。共通確認にintentを追加し投稿/更新/保存の文言を保持する。結果フォームの共有ガードとFABの旧確認が重なる問題も解消した。
- ガラスは全員共通の現在のtrue側を保持し、false側のメニュー/表示とフラグ呼出を撤去した。SystemGlassMarker、press listener、Portal、フォーカス復帰、reduced motion、タブのキーボード操作は保持。HomeNoticesの明日計算はjstToday(1)へ統一した。
- ロール名方式を設定方式へ置き換える権限変更は行わず、表示の説明判定を既存のcanModerateComments/canManageObMeetへ集約した。説明文は元checkoutの最新記述と実際の既存権限に合わせた。
- 相互レビューで取込APIの取得失敗、親の方式切替による保留状態消失、保存未達後の入力ロック、共有ガード導入時の二重確認を追加検出し、必要な範囲で修正した。
- FABの練習/大会/記録会切替と月次入力も共有ガードへ接続した。月次の一括保存は途中拒否・通信例外から待機解除し、保存済み行は保持する。結果不明は再送を止め、対象から除外された未保存行も成功終了・端末内入力削除の条件に入れない。同一batchの予定保存失敗から別insertへ進む経路と成功予定の二重作成を止めた。保存する本人IDは検証済みgetUserへ合わせた。
