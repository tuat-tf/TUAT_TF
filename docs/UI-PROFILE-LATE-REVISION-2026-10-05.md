# 専門種目と遅刻連絡の再調整（2026-10-05）

担当: Codex。所有者の訂正により、専門種目の常時全展開と、遅刻の有無まで全画面フォームで入力する構成を見直す。前回の[プロフィール・フォロー・遅刻](UI-PROFILE-ATTENDANCE-2026-10-05.md)はその時点の記録として残す。今回はフォローを変更しない。

## 再現と受入条件

- 現状は25種目が同時に表示され、プロフィールの入力画面が長くなる。専門種目の4カテゴリはすべて共通Disclosureで初期は折りたたむ。同じ操作で開閉でき、閉じた状態でも選択件数と選択済み種目が分かる。開閉や所属変更で選択を捨てず、保存失敗でも保持する。
- 現状の遅刻登録は入口→遅刻の選択→保存の3タップで全画面へ移る。通常の連絡と取消は共通Buttonから1タップで行う。任意理由だけ既存SheetとInputで編集する。閉じても書きかけを保持し、取消が確定した場合だけ理由を解除する。
- 送信中は連打と理由編集を止め、表示寸法を保持する。既知の拒否と0件更新を成功にせず元の状態・入力を残す。応答不明は既存atomicSaveによる読み取り確認へ切り替え、再送しない。取得失敗を「遅刻なし」「理由なし」へ置き換えない。再入場は既存の初期データ取得結果を使い、表示のための更新を送らない。
- Chrome/WebKitの320/390/1280pxで、カテゴリ開閉→選択→所属変更→保存、遅刻連絡→理由編集→閉じる→再開→保存→取消を確認する。失敗・0件・結果不明・再入場を合成通信で検証する。実機PWAと本番更新は別の未確認範囲とする。

- 新しいキャッシュ・状態管理基盤・共通層を追加していない。ページへ再入場した場合は既存の初期データ取得で得られた保存済み状態を使う。入力の保持は同じ予定カードで理由編集を閉じて再度開く操作を対象とし、ブラウザ終了や別ページへの移動をまたぐ永続下書きを追加していない。
