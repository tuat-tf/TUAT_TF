# 新UI版 — 管理者の端末別オプトイン（2026-10-01）

## 依頼と今回の範囲

オーナーは予定作成の崩れ、出欠表示のガラス化、戻るの「‹」化を依頼。その後、通常公開アプリと分け、管理者が設定でオンにする新UI版に変更するよう指示した。保存先は「この端末だけ」と確定。さらに「一括」は主要画面だけでなく旧UI全体の調査・刷新を指すと明確化されたため、認証後31ルートと、それらから開く編集・管理・共有・設定フォームまで対象を拡張した。

同じデータ・URL・操作を使う表示モードとして実装。初期状態はオフ。「マイページ → 設定 → 管理者設定 → 新UI版を使う」で切り替える。既存の公開下部タブは両モードで維持する。

## Apple公式の設計指針

- [HIG Materials](https://developer.apple.com/design/human-interface-guidelines/materials)：ガラスは操作・ナビゲーション層。文字量の多いメニューはregular相当とし、本文・一覧・入力フォーム全体をガラスにしない。
- [HIG Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons)：通常44×44ptの操作領域、押下反応、操作の優先度。
- [WWDC25: Get to know the new design system](https://developer.apple.com/videos/play/wwdc2025/356/)：操作元と展開面の関係、配置とグループによる階層。曖昧になる操作名は文字を残す。
- [HIG Segmented controls](https://developer.apple.com/design/human-interface-guidelines/segmented-controls)：同種の選択肢をまとめ、等幅と明確な選択状態を使う。
- [HIG Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)：色だけで意味を伝えず、文字・アイコン・読み上げ名と状態を保つ。
- [Testing system accessibility features](https://developer.apple.com/documentation/accessibility/testing-system-accessibility-features-in-your-app)：透明度低減・動き低減・キーボード等を検証する。

これはApple風のWeb表示。Appleネイティブの背景適応・屈折やChatGPTアプリの内部実装と同一ではない。共通のButton・Card・Input・Textarea・Select・Toggle・Disclosure・Sheet・FullScreen・確認ダイアログ・Toastまで新しい面、角丸、縁、選択色、押下反応へ統一した。本文・入力面は読みやすい明るい面、メニュー・選択リストなど浮遊する操作層には背景ぼかしを使う。内容の上にガラスボタンを重ねるだけの変更にはしない。

### 操作と負荷

- 記録項目の削除ボタンは新UIだけ44pxのヘッダー行へ移し、入力欄に重ねない。長いSelectの選択文は折り返し、モバイル入力は16px以上にして入力時の自動ズームを避ける。距離入力の単位は縮めず1行に保持。
- 投票は文字・チェック・aria-pressedを併用。投票者の切替は矢印/Home/End、選択とtabpanelの関連付けを追加。共有/コピーは直接activationを保持する共通GlassMenuへ統一。
- 新UIの画像拡大はRadixでフォーカスとスクロールを管理。Esc・閉じる・背景・元ボタンへの復帰を確認。写真調整も新UIだけモーダル内の初期フォーカス/復帰を補う。
- スレッド入力欄が下タブと26px重なる旧配置を新UIで解消。ResizeObserverで入力欄の高さを測り、末尾の余白を確保。visualViewport変化は1フレーム1回、DOM変数だけを更新し、メッセージ全件を再レンダーしない。解除時にobserver/listener/rAF/変数を掃除する。
- 通常のボタン・カード・出欠・メニューの入口・セグメント選択面は色/縁/陰影で統一し、各行にbackdrop-filterを追加しない。浮遊メニュー・選択リスト・入力欄・FABに限定。追加WebGL・追加画像化・ページ全体のMutationObserverなし。100行の実Card/Button合成一覧で各行のfilter/backdrop-filterが0であることを検証。
- 押下は1組のPointerリスナーを共有し、スクロール/キャンセル/離指で解除。セグメントの項目配列が親の入力再描画ごとに再作成されても、同一内容ならResizeObserverを作り直さない。透明度低減/高コントラスト/動き低減、シートのドラッグ復帰も考慮。

## モード・権限・状態

- 有効権限はgetCurrentProfileのmanageMembersまたはmanageSystem。ロールの名前では判定しない。一般部員プレビューは名前が残っても実効フラグがゼロなので無効。

# 新UIの位置ずれ・旧表示混在の修正（2026-10-01）

対象は管理者がこの端末で「新UI版を使う」を有効にした表示。通常版、部員の権限、保存処理、公開下部タブの光学処理は変更しない。

## 再現と原因

- 月別結果の矢印：既存の `p-2` に44pxの最小寸法だけを追加していた。Chrome 320pxでアイコン中心がガラス面の中心から縦横3pxずれていた。
- ノート写真の削除：既存の小さい余白付きボタンを同様に拡大し、アイコンが横8pxずれていた。
- ActionMenuの「…」：ページ内は44pxのガラス面だが、FormModalのPortal内は共通セレクタの対象外で32px・背景なし・角丸なしだった。
- SegmentedControl：`offsetLeft` / `offsetWidth` の整数化で、幅が割り切れないと選択面がずれた。変更前の合成画面では0.46875px差。実寸の再測定や百分率transformにもブラウザ差があるため、最終版は測定を使わない。
- 同じ操作部品でも従来の専用ガラスCSSと新UIの汎用CSSで白膜・縁・影が違い、複数行の選択行に丸いピルを当てていた。

## 修正

1. ボタン内容を中央配置し、26個のアイコン単独操作を明示的に分類。アイコンは余白なし・縮小なし、通常の文字操作は左右の余白を確保する。月送りの無効側も同寸法を保ち、月名が横に動かないようにした。投稿の項目行と体調タイルは専用の配置を維持。
2. Portal内を含めてガラス操作のCSS適用範囲を揃えた。通常の操作部と戻る・通知・操作メニューで共通の面・縁・影を使う。出欠の意味を持つ色は維持。
3. セグメントの選択面は、均等幅と2pxの間隔・内側余白からCSSの `left` と `width` を計算する。未選択なら面を出さない。DOM寸法の読取り・ResizeObserver・更新エフェクトを撤去。小数の幅・親フォームの拡大アニメーション・文字拡大にブラウザのレイアウト処理で追従する。
4. 設定・ロール・OB担当などの複数行選択は18pxの角丸の行に統一。横長の切替グループは共通の内側余白・背景・形に揃える。高コントラストの代替表示を選択行にも適用。
5. 投票タブは項目名と票数を別の領域にし、長い項目名だけを省略。中央配置へ揃えた後も票数が文字に接したり隠れたりしないようにした。

## 検証

ローカルの実Reactコンポーネントに合成データを与えて検証。実部員への書込みは行わない。
